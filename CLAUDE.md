# Sesquipedalian – project brief

Ground truth for every build step. Read it in full before changing anything. When a step adds detail, record it here.

## Purpose

**Sesquipedalian** is a Moira Rose vocabulary game for one family of four. One device is passed round the table and read aloud: the tester holds it and reads, the answerer guesses without seeing the screen. Single-page web app, no back end.

The repo (`KompassK/moirawordgame`) and folder (`moira-words`) keep their old names so the web address doesn't change: https://kompassk.github.io/moirawordgame/. Internal names such as `window.MOIRA_WORDS` also stay.

## Tech constraints

- Plain HTML, CSS and JavaScript. No framework, no bundler, no TypeScript, no build step for the app itself.
- Static files only. Must run by double-clicking `index.html` (`file://`) and from GitHub Pages. Keep every path relative (`./…`) because Pages serves from a sub-path.
- Node is used **only** for the build scripts (`npm run build`, `npm run icons`), never at runtime. `xlsx` (SheetJS, from the SheetJS CDN) is the only dependency; `@resvg/resvg-js` is the only dev dependency (icon rendering).
- No accounts, no analytics, no sharing, **no third-party requests** (fonts are self-hosted; the game works offline). All persistence is `localStorage`, and **only `storage.js` touches it** (see 'The device's memory').
- **An offline PWA (step 6).** `manifest.webmanifest` (step 2b) plus a service worker, `sw.js`, which precaches the app shell and caches stills on first use, so the game starts and plays with the network off. `sw.js` is **generated by `npm run build`** (from `scripts/sw.template.js`) with that build's version, so every build is a new worker – there's no version number to bump by hand. See 'Offline and updates'. Service workers need http(s): opened from `file://` the game plays normally, just without offline caching or update bars.
- Primary target: phone in portrait. Must also work on a tablet in either orientation.
- Keep the screen awake during a game with the Wake Lock API where supported; ignore silently if not.

## Look and feel

- **Black, white and greys only.** Background white (`#ffffff`; never darker than `#fafafa`), ink `#111111`, greys for panels (`#f5f5f5`), pills (`#ececec`), rules and muted text. No cream, brown, gold or rose. **The only colours anywhere are green `#35664a` on Correct and red `#a13c33` on Wrong.** (End game's confirm button is black, not red.)
- **Type:** Josefin Sans (self-hosted from `assets/fonts/`) for the title, the headline word, handover and final headings, badges, labels and buttons – always in **capitals with 0.08em letter-spacing**, like signage. Body text, the tester panel's definitions, quotes, the reveal card's sentences and small links use the system sans-serif. Josefin sits high in its line box, so signage elements get a little extra top padding.
- **Headline sizes:** the word aims for at least 44px on a phone and 72px on a tablet and is **always on one line**; `fitAll()` shrinks any `.fit` element (title, word, final heading) only if it would overflow its column (never below 28px, when it may wrap). Josefin capitals are wide, so on the dummy list: phone – 19 of 50 words shrink below 44px (smallest 33px, 'Discombobulate'); tablet portrait – 7 below 72px (smallest 62px); tablet landscape – none (smallest 86px). Accepted in step 2.
- Buttons are at least 56px tall (60px phone, 68px tablet); Correct and Wrong are taller still.
- Phone: turn-screen buttons are full width and **pinned to the bottom**, always in the same order – hint, Correct, Wrong – with two small text controls under them: **Give up** (left) and **Oops, go back** (right).
- Tablets, both orientations: the word full width on top; tester panel beside the quote and scene below; hint, Correct and Wrong in one row. (Step 1's two-column landscape layout was dropped because Josefin capitals don't fit a half-width column.)
- Bonus word screen: black background, white text – visibly different, within the palette.
- Tested at 390×844, 768×1024 and 1024×768.

## Data: spreadsheet → `words.json`

`scripts/build-words.js` reads the first `.xlsx` in `data/` – the **live** spreadsheet – or the file given as an argument (skipping Excel `~$` lock files; see below), sheet `Words`, row 1 = headers. Columns are matched by **exact header text**, never by position. The build fails loudly if a required header is missing, if any Y/T row has an empty Word, Definition or Keywords, or on a bad ID, Include value or season/episode number. Everything the build prints identifies rows by **row number and ID only** (see Privacy of the live data).

| Header (exact) | JSON field | Notes |
|---|---|---|
| `ID` | `id` | integer, unique |
| `Word` | `word` | |
| `Definition (game answer)` | `definition` | |
| `Acceptable gist / keywords for judging` | `keywords` | one string; semicolons may separate alternative senses; kept as-is |
| `Moira's twist (other sense / how she bends it)` | `twist` | null if empty |
| `Quote` | `quote` | **never altered by code**; null if empty |
| `Season` | `season` | integer or null |
| `Episode` | `episode` | integer or null |
| `Episode title` | `episodeTitle` | null if empty |
| `Scene context` | `sceneContext` | null if empty; written to follow the lead-in 'In this scene, ' |
| `Image file` | `imageFile` | null if empty |
| `Quote printed on photo? (Y/N)` | `quoteOnPhoto` | boolean |
| `Include in game? (Y/N)` | `pool` | `"main"` for Y, `"bonus"` for T; N or blank rows are dropped |
| `Invented example sentence (bonus hint - NOT a real show quote)` | `exampleSentence` | null if empty; only bonus words have one |
| *(derived)* | `quoteGroup` | words with identical quote text (trimmed, whitespace collapsed) share an integer id; no quote → null |

All other columns are ignored. `Bonus point available? (Y/N)` is retired; do not read it. `clues on where its'f rom`, `Timestamp`, `Image type`, `Sources`, `Verification` and `Notes / issues` are editorial.

```json
{
  "generatedAt": "ISO timestamp",
  "source": "filename of the xlsx",
  "datasetId": "ece7ae2a-230",         // FNV-1a hash of the source filename + '-' + number of words (dummy: f7f1920f-50)
  "words": [ { "id": 9001, "word": "…", "definition": "…", "keywords": "…", "twist": null,
               "quote": "…", "quoteGroup": 1, "season": 1, "episode": 1, "episodeTitle": "…",
               "sceneContext": "…", "imageFile": "…", "quoteOnPhoto": false,
               "pool": "main", "exampleSentence": null } ]
}
```

### Live data (step 7)
- **Source:** `data/Moira words database.xlsx` – 242 rows: **170 Y (main), 60 T (bonus), 12 N** (dropped). 230 words in `words.js`, dataset identifier `ece7ae2a-230`.
- **Capacity:** the player cap stays at 4. A 4-player Option 1 game uses **36 main + 4 bonus** words (9 + 1 per player), well inside 170 / 60, so `PLAYER_LIMIT` = min(4, ⌊170 ÷ 9⌋ = 18, 60) = 4. The pool 'reset' is unchanged: least-asked-first (see The device's memory) simply dips into the least-asked words once the never-asked ones run out.
- **Shared quotes:** 27 `quoteGroup`s have more than one word; the largest has 3. The within-turn exclusion is tested against the real groups.
- **The three known quirks, all handled by the game** (the build lists them by ID at every run):
  1. **ID 113** (main) has **no quote and no season/episode**. It's kept. The hint ladder skips 'Read the quote': the hint button says **Show the photo** straight away and the points step **4 → 2** (a wrong guess first still caps it at 1). With no quote there's no overlay on its photo, **no scene text** on the turn screen and **no 'In this scene' line** on the reveal card. Note: its Scene context cell is *not* empty in the sheet (172 characters), but a scene line without its quote is never shown. It is never in Options 2 or 3.
  2. **IDs 25, 32, 66, 100** (main) have **no image file**: the placeholder still, with the quote drawn over it.
  3. **14 main words** have 'Quote printed on photo?' = Y (the step 7 brief said 27; the sheet has 14): their photo is shown without the overlay.
- **Also flagged by the build:** **ID 54**'s quote has no word starting with its word's first five letters, so Fill in the blank can't blank it (the tester sees the data warning). Fix the quote or the word in the sheet.
- **Bonus words' image files:** the bonus rows name an image too (one shared file), but the game never shows a bonus word's photo.

### Privacy of the live data
- **The spreadsheets are not in the repo** (they hold the answers): `.gitignore` has `data/*.xlsx`, `data/**/*.xlsx` and `data/images/`, and the dummy spreadsheet was removed from git in step 7 (`git rm --cached`; it stays on disk as the fixture; no history rewrite). **The build needs them present locally.** Committed: only the generated `words.json` / `words.js` and the referenced stills in `assets/stills/`.
- **Never print a live word, definition, quote, scene context, episode title or still filename** – in the build's output, test output, commit messages, or anything shown to Katharine (she plays the game). Use counts, IDs and column names. Live still filenames usually contain the word (135 of 226 references), so the build's stills warnings list **IDs**, not filenames, and git commands that would list `assets/stills/` must run quietly (`git commit -q`; pipe `git status --short` to a count).
- `tests/index.html?data=live` hides failure messages (they could contain a word) and shows only where a test failed.

### The dummy test set
- `data/dummy/Moira words database - DUMMY TEST DATA.xlsx` (36 main, 14 bonus, no shared quotes; not in the repo). **`npm run build -- "data/dummy/Moira words database - DUMMY TEST DATA.xlsx"`** builds it into the **test fixture** `tests/fixtures/dummy-words.js` / `.json` (committed) and touches nothing the game ships: no `words.js`, `version.js` or `sw.js`. Its dataset identifier is `f7f1920f-50`.
- Four of its words point at the test stills (Image file column) – 9001 → `test-16x9.jpg`, 9002 → `test-4x3.png` (and 'Quote printed on photo?' = Y), 9003 → `test-1x1.webp`, 9004 → `test-3x4.png`. The other 32 dummy words name made-up `dummy_*.jpg` files that don't exist, so the dummy build prints one missing-stills warning; that's expected.
- Rebuild and commit `words.json` and `words.js` whenever the live spreadsheet changes; rebuild the fixture if the dummy one does.

### Stills: `assets/stills/` (step 5)
- Each word's `imageFile` (Image file column) names a file in **`assets/stills/`**, exactly as written in the spreadsheet (same spelling and case – GitHub Pages is case-sensitive), no folders. Formats: **`.jpg` / `.jpeg`, `.png`, `.webp`**. Files are used as they are: no resizing at build time yet.
- The build checks every referenced file exists and is an accepted format, and lists any that aren't as a **warning** (never an error; `scripts/check-stills.js`).
- In the game, no `imageFile`, or a file that fails to load, falls back to `assets/placeholder.svg` silently.
- Fixtures in `assets/stills/`: `test-16x9.jpg`, `test-4x3.png` (carries its own quote), `test-1x1.webp`, `test-3x4.png` – plain grey rectangles labelled with their ratio. Keep them; the tests use them.
- **Live stills (step 7):** the live sheet's Image file column names **138 distinct files**, all used by main words; all 138 were copied from `data/images/` into `assets/stills/` (8.6 MB), exact names, none missing. The 22 unreferenced files in `data/images/` were not copied. To add or change stills: put them in `data/images/`, copy the referenced ones across under their exact Image file names, rebuild, and check the build prints no missing-stills warning.

## Screens and flow

**Front card** (on opening, and after End game) → **How to play** (players and names) → handover → turns → reveal after every word → pass-the-device between turns → **final scoreboard** → optional **tiebreak**.

### Front card
- The title 'Sesquipedalian', large; the line 'A Moira Rose vocabulary game'; then this intro, **word for word** (in `UI.intro`):
  > We all love Moira Rose but it's fair to say she was a sesquipedalian. Still we can all learn from her wonderful use of words. The aim of this game is to test our knowledge and understanding of her vocabulary. Highest score wins.
- Then 'There are three ways to play:' and the **three way-to-play boxes**, where the way to play is chosen:
  - **Define the word** – 'Say what the word means. Hints cost points. Up to 4 points a word, 5 for the bonus word. 2–4 players.'
  - **Fill in the blank** – 'Supply the missing word from the quote. 1 point a word. 2–4 players.' and, under it, the playable set ('32 words to play').
  - **Name the episode** – 'Which season and episode is the quote from? 1 point for the season, 3 for both. 2–4 players.' and the playable set.
  - Each box: a one-line description, its scoring, the player range. A locked box is dashed, greyed, can't be chosen, and shows **only** 'Play a Define the word game first to unlock this mode' and, under it, the progress ('4 of 10 words played'). Description, scoring, player range and playable set appear once it unlocks (see Unlock rule; `isUnlocked()` in `game.js`). A word joiner keeps '2–4' together on one line.
  - **This is where the way to play is chosen** (the brief's 'setup screen with the option cards'). New game, End game and a finished game all come back here.
- A big **Start** button goes to How to play. If there's a saved game (see Saving and resuming), **Resume game** (black) sits above Start (then outlined), and Start first asks 'Abandon the saved game?' – **Abandon it** / **Keep it**.
- A small grey **gear** at the top right opens the Settings card (see The device's memory). The front card's content starts below the gear.

### Rules overlay
A small **Rules** link on the How to play screen and on the pass-the-device screen opens the front card's content as an overlay – title, tagline, intro – followed by 'How to play' for all three ways to play. Close with the **Close** button or Escape.

### How to play (in `UI.gameTypes[…].rules`)
**Define the word** – supplied by Katharine; obvious typos fixed ('asked to define', 'had a turn', '3 points'), otherwise as written:
1. Everyone takes a turn to be asked to define 10 words. The player on your left holds the phone and reads out the words for you to define: nine from the show's dialogue and one Catherine O'Hara loquacity masterclass as a bonus. Once everyone has had a turn, that's the end of the round. Highest scorer wins.
2. For each word, say what it means. Guess it cold for 4 points. You can ask to hear the full quote – but if you do, your score will drop to 3 points. Ask to see a photo of the scene with the quote and the score drops to 2. A wrong guess always drops your possible points for that word to 1, but you can keep going with hints and get the point if you get it right. Any real meaning of the word counts, including the one Moira had in mind.
3. The bonus word has no quote. Guess it cold for 5 points, or hear it in an invented sentence first for 3. Guess wrong, then hear the sentence and get it right, for 2.
4. Stuck? You can give up on any word at any time. It counts as a pass: no points for that word, and you move on to the next one. You still get 10 words in all. *(Added in step 2 at Katharine's request.)*
5. The asker judges. Adults decide what's close enough.

**Fill in the blank** and **Name the episode** – drafted in the same voice from the rules below. Each says 'Everyone takes a turn of **9** questions' (step 4's brief; Katharine's earlier answer was 10 – see Open questions) and includes the Give up / pass line. Fill in the blank adds 'saying 'blank' for the missing word' and 'Any form of the word counts if the table agrees'; Name the episode adds 'its number or its title' and 'the episode isn't asked' after a wrong season.

### How to play (the second screen: set-up)
- A top bar with **‹ Back** (to the front card, to change the way to play) and **Rules**.
- The chosen way to play's name as the **title** (e.g. 'Define the word', shrunk to fit one line if needed), **How to play** as the subtitle under it, then its how-to-play text.
- **Number of players: 2, 3 or 4, for every way to play.** Every game needs a tester and an answerer, so there is no solo mode; five and six don't exist. (`MIN_PLAYERS` / `MAX_PLAYERS` in `game.js`.) For Define the word the pool-size check stays (the dummy list supports 4) but won't bite.
- Names in seating order (clockwise), **pre-filled with the names from the last game** on this device (and the player count set to match). A blank name becomes 'Player N', so a game can start in three taps (Start, Start the game, ready). **Start the game**.
- Options 2 and 3 only: a line under the player count – '9 words per turn, from the 32 you've played.' – showing the reduced number when the playable set is small (see Options 2 and 3). If there aren't enough for even one word each, it says so ('Only 3 played words to use – not enough for this many players. Play more Define the word first.') and **Start the game** is disabled.
- Phone: all of this in one column with Start the game pinned; tablet: how-to-play text left, players and names right.
- Words per turn is fixed, not configurable (only reduced automatically in Options 2 and 3).

### Turns
- Player 1 is the first **answerer**. The **tester** is always the next player in seating order (to the answerer's left) and holds the device and reads aloud. After each turn the answerer moves one seat on.
- A round is one pass in which every player has one turn. **A game is one round.**
- Option 1 turn: 9 main-pool words, then 1 bonus-pool word (always the tenth and last). Options 2 and 3: 9 words, no bonus word (fewer if the playable set is small).
- **Every turn screen** (Option 1 main and bonus words, Options 2 and 3) has a small grey **End game** in the top-right corner, beside 'Testing: …', with the same confirm as elsewhere. The photo screen has none: the whole photo is a 'tap anywhere to go back' area and is facing the answerer; End game is on the turn screen it returns to.
- Before the first turn a handover screen says 'Pass the device to [tester]' with an 'I'm [tester], ready' button, so nothing is shown until the tester has the device.
- After each turn except the last: pass-the-device screen – 'Pass the device to [next tester]', the answerer's score for the turn, a mini scoreboard, 'I'm [next tester], ready', and two small links: **Rules** and **End game**. After the last word of the last turn the reveal card's button reads 'See the final scores'.

### Draw
- Per turn (Option 1): 9 main words, then 1 bonus word, least-asked first (see The device's memory). Options 2 and 3: their words per turn from the playable set, least-asked first by that option's own counts. No word is drawn twice in a game (tiebreak words included).
- Shared quotes: once a main word is drawn, other words with the same `quoteGroup` are excluded from the rest of that turn. Only if the pool is too small to avoid it is a sibling allowed (logged as a console warning).

### Option 1 – main-pool words (hint ladder)
The tester's screen, top to bottom: 'Testing: [answerer] · Question n of 10'; the word, very large; a **Points available** badge; a tester-only panel (definition, keywords, and the twist if present – headed 'Any of these senses counts'); then the quote and scene context, **dimmed until 'Read the quote' is tapped**. The answerer must not look. The tester says the word, then:

| Rung | Action | Badge |
|---|---|---|
| 1 | Guess on the word alone | 4 |
| 2 | Tester taps **Read the quote** (quote and scene stop being dimmed), reads it aloud | 3 |
| 3 | Tester taps **Show the photo**: the photo screen (see below); tester turns the device round; a tap anywhere returns. | 2 |

**The photo screen** (step 5): full-screen, black, the still fitted inside (**contain**: nothing cropped, letterboxed if needed), either orientation, nothing else on screen. The frame takes the image's own shape once it loads (`--r`, set by `game.js`), so unless `quoteOnPhoto` is true the quote is drawn **over the lower part of the picture itself**: white on a translucent black band, centred, wrapping, at least 24px on a phone and growing with the picture (up to 44px), the word in the display font (Josefin capitals) and the rest in the body font. When `quoteOnPhoto` is true the image is shown alone. While it's up the app asks the browser to hold the current orientation (`holdOrientation()`); iPhones never allow that and Android only in fullscreen, so it usually fails silently and both orientations are laid out properly instead. Option 3's inline still uses the **same renderer** (`renderStill()`), smaller, overlay included.
- Stills load lazily: a word's still is fetched when its question comes up, and the next word's while the current one is on screen (`prefetchStills()`); nothing at page load.

- After the photo, the hint button becomes **Show the photo again**: it re-opens the photo as often as wanted and **never changes the points**.
- **Correct** scores whatever the badge shows and goes to the reveal card.
- **Wrong before the last hint** drops the badge to 1 for good ('Not quite. This question is now worth 1 point – keep going.'). The answerer can keep guessing at 1 point as long as they like (intended); later hints don't change the badge.
- **Wrong after the photo** scores 0 and goes to the reveal card. So: eventually right → 1; never right → 0.
- **Give up** (small, under Wrong) is a **pass**: 0 points for that word at any point, **straight to the reveal card**, then Next moves on. It never draws a replacement – every turn is still exactly 10 words. It **can be undone** with 'Oops, go back' on the reveal card. Give up exists in all three ways to play. (Keeping the screen hidden from the answerer, except for scene photos, is the tester's job, not the app's.)
- **Oops, go back** (small, under Wrong) undoes the last tap on this question – a hint, a mis-tapped Wrong, anything – as many steps back as the question has had taps. It restores the question exactly, including the badge and the dimming. It is disabled before the first tap. Opening the photo again is not a tap that needs undoing.
- Judging: the definition is visible to the tester throughout; the table agrees and the tester taps Correct or Wrong. Any sense of the word counts: if `twist` is present, either meaning scores the full ladder value. No extra point for a second meaning.

### Catherine O'Hara bonus word (bonus-pool words)
- Black screen, a 'Catherine O'Hara bonus word' badge, the word very large, a Points available badge, and a tester-only panel with definition and keywords. No show quote, no photo.
- Two buttons: **Hear it in a sentence** and **Guess**. 'Guess' swaps to Correct / Wrong. 'Hear it in a sentence' shows `exampleSentence` directly under the word, in a dashed box (deliberately unlike a show quote), captioned 'Not a real quote – just for the game', then shows Correct / Wrong.
- Scoring:
  - cold guess right → **5**
  - sentence first, then right → **3**
  - wrong cold, then sentence, then right → **2**
  - wrong after the sentence → **0**
- After a wrong cold guess the only path is the sentence (Guess is disabled). One guess only after the sentence. The app records whether a cold guess was tried (`coldTried`) before the sentence was requested.
- **Give up** and **Oops, go back** work exactly as on main words.
- If a bonus word has no `exampleSentence`, the sentence button is disabled and a wrong cold guess scores 0.

### Reveal card (after every word)
- Right: 'Yes, you're right!', then **the definition underneath in smaller text**: '[Word] means [definition].'
- Wrong or given up: 'Sorry, that's not right – [Word] means [definition].'
- The definition's first letter is lowercased when its first word is 'A' or an ordinary capitalised word (not 'I', not an all-capitals word), and a trailing full stop is dropped.
- Then, only when `sceneContext` is non-empty (so never for bonus words): 'In this scene, [sceneContext].' – the scene text is used as written, only a trailing full stop is dropped.
- The points for the question ('+3 points', or 'No points') and the answerer's running total.
- A big **Next** button and an **Oops, go back** link that restores the question as it was before the tap that ended it (and takes the points back off), with its own undo history intact.

### Final scoreboard
- Ranked names and totals (equal scores share a rank).
- One leader: '[Name] wins!'. Level at the top: 'Tied', the tied names, a one-line explanation, and a **Tiebreak** button.
- **Play again** starts a new game straight away with the **same way to play and the same players**. **New game** goes to the **front card**, where the way to play is chosen (the last one stays selected; names are pre-filled on How to play). A small **End game** link (with confirmation) also returns to the front card.

### Tiebreak
- Offered when the top score is shared. The tied players, in seating order, each answer one Catherine O'Hara bonus word per round, scored exactly as a normal bonus word and added to their totals. The tester is the next player round the table, as usual, with a pass-the-device screen before each word ('Tiebreak – round n', the tied players' scores).
- Words: any bonus word not yet drawn in *this* game, **least-asked first** (same rule as the main draw), so never-asked words come first and then bonus words from earlier games are reused. Tiebreak words count as asked – in Option 1's (bonus) history, in every way to play, because they are Option 1-style questions.
- The same in all three ways to play: an Option 2 or 3 tiebreak uses bonus words scored as in Option 1.
- After each full round, if one player is ahead, they win ('[Name] wins!', 'Won on the tiebreak'). If not, anyone behind the leaders drops out ('Still level: A and B. Another round.') and the leaders play another round. (Drop-out confirmed by Katharine.)
- If there aren't enough unused bonus words for every remaining player to have one in the next round, it's a **Draw** ('The bonus words have run out, so it's a draw between A and B.').

### End game
A small **End game** on **every turn screen** (top-right corner), the pass-the-device screen and the final scoreboard. It asks 'End this game? Scores will be lost.' – **End game** (black) or **Keep playing** (or Escape) – then clears the saved game and returns to the front card. Mid-question, the question isn't scored (and it already counted as asked, since it reached the screen).

## Options 2 and 3 (step 4)

### Common to both
- Open only once unlocked (see Unlock rule). Lighter variants of the Option 1 turn: same top line with End game, points badge, tester-only panel, pinned buttons, Give up and Oops, go back underneath; same pass-the-device, scoreboard, End game, Resume and tiebreak (tiebreak still uses bonus words, scored as in Option 1).
- **The playable set** (`playable()` in `game.js`): main-pool words with an **Option 1 history on this device** (asked at least once in Define the word) **and a quote**. Name the episode also needs the season and episode number (otherwise there's nothing to judge). Never bonus words, never words not yet asked in Option 1. Shown on the front card box ('32 words to play').
- **Words per turn: 9**, no bonus word. If the playable set is too small for every player to have 9, the turn shrinks so everyone gets the same: ⌊playable ÷ players⌋ (`optionPerTurn()`), and the How to play screen says so ('8 words per turn, from the 32 you've played.'). 0 means Start is disabled.
- Same turn structure as Option 1: 2–4 players in seating order, the tester to the answerer's left, one turn each, device passes left, one round.
- Same **least-asked-first** draw and shared-quote exclusion, but each way to play has **its own ask-counts** (`counts.blank`, `counts.episode`), so playing Option 2 never skews Option 1's draws or its history.
- **Give up** = pass, 0 points (see Open questions for Option 3 after a right season).

### Option 2 – Fill in the blank
- Turn screen: points badge (1); the quote, large, with the target word replaced by a **blank** – a rule as long as the word; 'Read it aloud, saying 'blank' for the gap.'; tester-only panel: **The answer** (the word) and its definition.
- Buttons: **Correct** (1 point) / **Wrong** (0). One guess. Any inflection the table agrees on counts; the app doesn't judge.
- **Blanking** (`blankQuote()`): a word in the quote matches if it starts with the **first five letters** of the spreadsheet's word (its first word, letters only, case-insensitive) – so 'Squire (verb)' finds 'squired' and 'squiring', 'Haughty' finds 'haughtily'. Every match is blanked; an apostrophe-s stays visible. The quote text is never changed – it's only split for display. **No match:** nothing is blanked and the tester panel shows a dashed warning ('Couldn't find 'Word' in this quote, so nothing is blanked. Please check the spreadsheet.') so the data can be fixed.
- Reveal card: 'Yes, you're right!' or 'Sorry, that's not right – the word was [Word].'; the **full quote with the word highlighted** (grey highlight, bold); then 'In this scene, …' as in Option 1; points and running total.

### Option 3 – Name the episode
- Turn screen: points badge (3); 'Season first, then the episode – its number or its title.'; the quote, large; tester-only panel: **The answer** ('Season 2, episode 3') and the episode title; then the **still, inline** (when the word has an `imageFile`) – drawn by the same renderer as the photo screen, smaller (at most 32% of the screen height), with the same quote overlay unless `quoteOnPhoto` – below the answer so the answer is never pushed under the buttons; the tester scrolls to it and turns the device round.
- Buttons: **Season correct** / **Season wrong**; after a correct season ('Season right: 1 point. Now the episode – 2 more if right.'), **Episode correct** / **Episode wrong**. Scoring: season wrong **0** (the episode isn't asked); season right, episode wrong **1**; both **3**. The tester judges the episode on number or title; if the table agrees, it's correct. Oops, go back undoes the season tap.
- Reveal card: 'Yes, you're right!' / 'Right season, wrong episode.' / 'Sorry, that's not right.'; then 'Season 1, episode 4: 'Test Episode Four'.'; then 'In this scene, …'; points and running total.

## The device's memory (step 3)

### Storage schema – `storage.js`
One `localStorage` key, `sesquipedalian`, holding:
```json
{
  "schemaVersion": 2,
  "names": ["Kath", "", "Alexis"],
  "datasets": {
    "f7f1920f-50": {
      "counts": {
        "define":  { "9001": { "n": 2, "last": "2026-11-15" } },
        "blank":   { "9001": { "n": 1, "last": "2026-11-15" } },
        "episode": {}
      }
    }
  },
  "savedGame": { "datasetId": "f7f1920f-50", "savedAt": 1794770000000, "game": { … } }
}
```
- **`datasets[datasetId].counts[option]`** – per way to play (`define`, `blank`, `episode`), per word ID: `n` = times asked on this device, `last` = local date last asked. `counts.define` is the **Option 1 history**. Keyed by the dataset identifier from `words.js`, so a different spreadsheet (the live one at step 7) automatically starts with no usage and no saved game.
- **`names`** – the last game's names in seating order, as typed (blanks stay blank, so 'Player N' isn't remembered), up to 4. Not per dataset: they survive the switch to live data.
- **`savedGame`** – the game in progress (see below), with the dataset it belongs to and when it was saved.
- **`schemaVersion` is 2** (step 4). `migrate()` in `storage.js` converts old records one version at a time: **v1 → v2** moves step 3's `datasets[id].words` (Option 1 counts) to `counts.define` and adds empty `blank` and `episode`. Anything unrecognised – a newer version, or corrupt JSON – starts fresh.
- Every read and write is wrapped in try/catch. If storage is unavailable or full, the game plays normally and remembers changes for the session only; the Settings card then says nothing will be remembered.

### Asked, and the two pools
- A word counts as **asked** the first time it reaches the turn screen (`markAsked()`, called from `render()`) – not when drawn – and is recorded under the way to play being played (`optionOf()`; bonus words, including tiebreak words, always under `define`). Words drawn but never shown (e.g. after End game) don't count. Re-showing a question after a resume or an undo doesn't count again.
- The main and bonus pools cycle independently.
- **Least-asked first** (`leastAskedFirst()` in `game.js`, by that way to play's own counts): every draw takes words with the lowest ask-count first – never asked, then asked once, then twice – at random within each band. This **replaces the explicit 'reset' step**: when a pool's unused words run short, the draw simply dips into the least-asked ones. No flags to reset.
- Within a game no word is drawn twice, and the shared-quote exclusion within a turn still applies.

### Unlock rule
The Option 1 history is derived from the ask-counts (a word is in it if `n > 0`); it isn't stored separately. Options 2 and 3 unlock when **10 or more main-pool words** have been asked on this device (`UNLOCK_WORDS`). Bonus words don't count. While locked, the boxes show 'n of 10 words played'. Options 2 and 3 draw only from words in the history (see Options 2 and 3). Playing Options 2 and 3 never adds to it.

### Saving and resuming
- The whole game in progress is saved after **every tap** (`persist()` after each click), with words saved by ID. Undo history isn't saved.
- On opening, a saved game for this dataset that is **under 24 hours old** puts **Resume game** on the front card. Older saves are ignored.
- Resuming always lands on a pass-the-device screen, so nobody can gain from a refresh:
  - saved **mid-question** (turn screen or photo): the same question again **from its start**, nothing scored for it (points are only added when a question ends) – via 'Pass the device to [tester]', then the question;
  - saved on a **reveal card**: that result stands, and play moves on to the next word (via a pass-the-device screen, or the scoreboard if it was the last word);
  - saved on a **handover or pass-the-device screen**: exactly as it was.
- The saved game is cleared on the **final scoreboard**, on **End game**, when a new game starts, and on **Abandon it**.

### Settings card (gear on the front card)
- **Remembered names** (or 'None yet – names are remembered after a game starts.').
- **Words played**: 'Main: 23 of 36 played' and 'Bonus: 6 of 14 played'.
- **Reset word history** (outlined) with a confirm ('Reset word history? … Names and any saved game are kept.' – **Reset** / **Cancel**): clears the usage for the **current dataset only**. Not the saved game, not the names, not other datasets.
- **Add to home screen** (outlined, step 6) – Android/Chrome only, and only once the browser has offered an install prompt: `pwa.js` catches `beforeinstallprompt` and holds it, so nothing pops up uninvited; the button shows the browser's prompt. It disappears once installed.
- On iPhone/iPad, when not already running from the home screen: the one-line hint 'In Safari: Share → Add to Home Screen' (iOS has no install prompt).
- **Close**.

## Offline and updates (step 6)

### What's cached
- **The app shell** – every file in `scripts/shell.js`: `index.html`, `style.css`, `version.js`, `words.js`, `storage.js`, `pwa.js`, `game.js`, `manifest.webmanifest`, both fonts, `placeholder.svg`, all icons. Precached when a new worker installs, fetched fresh from the network (bypassing the HTTP cache), in a cache named for that version; older shell caches are deleted when the new worker takes over. Served **cache-first**.
- **The build checks the list**: it finds every local file the page loads (`index.html`'s `src`/`href`, `style.css`'s `url()`, the manifest's icons, `'./assets/…'` paths in the scripts) and **fails** if one isn't listed, or if a listed file doesn't exist.
- **Stills** (`assets/stills/`): cached on first use (in practice when the word's question comes up – see Stills), **cache-first**, in one cache kept across versions, capped at the **60 most recently used** (a hit counts as use). Offline and not cached → a network error, and the page shows the placeholder and doesn't try that still again this session. A missing file (404) isn't cached.
- **Navigations**: the scope itself (or `index.html`) gets the cached page; any other path inside the scope (a stale deep link) is redirected to the scope. Off the service worker (first visit, or `file://`), GitHub Pages' `404.html` does the same redirect.
- Everything is relative to the worker's scope – `/moirawordgame/` on GitHub Pages, `/` locally – never the site root (`./sw.js`, `./assets/…`).

### Update strategy: never a stale shell silently
1. Every build writes a new `sw.js` (its version is the commit hash plus the build time, the same as `version.js`), so every push is a new worker.
2. The browser checks for a new `sw.js` when the game is opened; `pwa.js` also asks when the front card or scoreboard shows (at most once a minute).
3. The new worker installs alongside and **waits**. The running game keeps its own version's files throughout – nothing is swapped mid-game.
4. On the **front card** and the **final scoreboard only** (never mid-game), a slim black bar at the top: **'New version available – tap to update'**, with the **new version's stamp** under it ('v 79b8b11 · 15 Nov 2026 20:04') to match against the latest commit.
5. Tapping it tells the waiting worker to take over (`SKIP_WAITING`); the page reloads once into the new version. A saved game survives (it's in `localStorage`).

### Version stamp and the release routine
The front card shows, in small grey text under Start, e.g. 'v bb6c901 · 15 Nov 2026 19:20': the commit the build was made on and the build time (device's time zone), from `version.js`. A `+` after the hash ('v bb6c901+') means the build included uncommitted changes. A file can't contain the hash of its own commit, so the stamp always names the **code commit it was built on**. To get a clean stamp:
1. Commit the change.
2. `npm run build` (writes `version.js` with that commit's hash, no `+`).
3. Commit `version.js` ('Stamp version') and push.

The build also writes `sw.js` with the same version, so the commit that stamps `version.js` must include `sw.js` (and `words.js`/`words.json`).

**Seeing an old version on the phone?** Wait for the bar ('New version available – tap to update', on the front card or scoreboard) and tap it, or hard-refresh. Give GitHub Pages a minute or two to publish after a push first. The bar shows the new version's stamp, to match against the latest commit.

### Icons and share image
- Text in both SVGs is Josefin Sans Bold converted to paths (made once from the TTF with opentype.js), so they render the same everywhere; only the share image's tagline is live text in the system sans-serif.
- The border has rounded corners (radius about 18%) so iOS's rounded-square crop doesn't cut its corners off.
- The maskable icon is `icon.svg` without the border (Android crops maskable icons to its own shape and only guarantees the central circle of radius 40%; the 4% border would be clipped). The S at 60% height sits inside that circle.
- Share previews need the site to be public on GitHub Pages; `og:image` and `og:url` are absolute URLs to https://kompassk.github.io/moirawordgame/. Messaging apps cache previews, so an old preview can linger after a change.
